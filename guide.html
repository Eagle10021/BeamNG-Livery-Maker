Livery Studio Guide

Design a skin in the studio, then turn it into a mod BeamNG.drive loads.
Watch the video tutorial
Mod setup based on tutorials by BNGF Plus & Top Tier Studios

1. Using the studio

Pick a template (File › Choose template), then build the livery in layers on top of it. Everything stays editable: shapes, text and gradients are vectors until you choose to rasterize them.

Select V Move, resize and rotate. Corners keep proportions (Shift stretches), Alt resizes from the centre. Double-click a shape to move its points.
Shapes U 28 shapes, drawn by dragging. Fill with a colour or a gradient, add an outline.
Pen P Click for corners, drag for curves, click the first point to close.
Text T Racing and display fonts, outline, letter spacing and a Curve slider that bends it along an arc.
Brush B / Eraser E Painting goes into a paint layer; the eraser works on the selected layer or all of them.
Fill bucket F Fills a panel of the template with colour. Set Sample: Template only to fill between the template's lines.
Gradient G Drag across a selected shape, or across the texture for a new gradient layer.
Linked mirror Mirror ↔ makes a copy on the other side of the car that follows every move and change, so both sides match.
Your work is kept: the studio saves to this browser as you go, and File › Save project writes a .livery.json file you can open again or share.

2. Templates

A template shows how the car's body is laid out flat (its UV map). Paint over it and the paint lands on those panels in game. There are two places to get one:

A

Included templates

40 vehicles, from the Skin Helper mod by Beamer XD. Pick one in File › Choose template.

B

From your BeamNG install

Every vehicle, including new ones: File › Open from your BeamNG install, then choose the vehicle's .zip. The studio lists the game's own UV templates and the vehicle's existing skins.

The vehicle zips are in the game's folder under content/vehicles/, for example:

Windows (Steam): C:\Program Files (x86)\Steam\steamapps\common\BeamNG.drive\content\vehicles\
Linux (Steam): ~/.local/share/Steam/steamapps/common/BeamNG.drive/content/vehicles/

The zip is read in your browser; nothing is uploaded. In Chrome and Edge you can choose the whole vehicles folder once and pick from a list after that.

  • UV templates open at the size of the vehicle's real skins (often 4096 × 4096), even when the template picture is smaller.
  • Existing skins open as a layer you can paint over. Files ending in _p.color.dds are palette skins: their red, green and blue areas take the car's three paint colours in game.
  • All DDS formats the game uses open directly, BC7 included.

3. Mod folders

Export the skin (Export, top right), then make this folder structure in your mods folder. [vehicle] is the vehicle's folder name, the same as its zip in content/vehicles (for example pickup or percheron).

mods/unpacked/[mod_name]/
└── vehicles/
    └── [vehicle]/
        └── [skin_name]/
            ├── skin.materials.json
            ├── [vehicle]_skin_[skin_name].jbeam
            └── [vehicle]_skin_[skin_name].dds (the exported texture)

The mods folder is in BeamNG's user folder: %LOCALAPPDATA%\BeamNG\BeamNG.drive\current\mods on Windows, ~/.local/share/BeamNG/BeamNG.drive/current/mods on Linux.

Names must match

The skin name in the jbeam, the material's name and the texture path in the material all have to match exactly, letter case included. Most "my skin doesn't show" problems are a name that differs somewhere.

4. Mod files

A. The jbeam: adds the skin to the Paint Design list

Current BeamNG vehicles register skins like this (from the game's own [vehicle]_skins.jbeam files):

{
  "[VEHICLE]_skin_SKINNAME": {
    "information": {
      "authors": "Your Name",
      "name": "My Custom Skin",
      "value": 200
    },
    "slotType": "paint_design",
    "skinName": "SKINNAME"
  }
}

Older mods use "globalSkin" instead of "skinName".

B. The material: puts your texture on the car

The safest way is to copy one of the vehicle's own skins: open the vehicle's zip, find its skin.materials.json (for example vehicles/pickup/skin.materials.json), copy one entry, and change three things:

  1. the entry's key, "name" and "mapTo": replace the old skin's name with yours, keeping the part before it (pickup.skin.SKINNAME);
  2. the texture path in the second stage: point it at your exported .dds;
  3. if the entry you copied is a palette skin (it has "colorPaletteMap"), use the full-colour form below instead, since the studio exports a full-colour texture.

A full-colour skin layered over the car's paint looks like this; where your texture is transparent, the car's own paint shows through:

{
  "[VEHICLE].skin.SKINNAME": {
    "name": "[VEHICLE].skin.SKINNAME",
    "mapTo": "[VEHICLE].skin.SKINNAME",
    "class": "Material",
    "Stages": [
      {
        "ambientOcclusionMap": "/vehicles/common/[VEHICLE]/[VEHICLE]_main_ao.data.png",
        "baseColorMap": "/vehicles/common/[VEHICLE]/[VEHICLE]_main_b.color.png",
        "metallicMap": "/vehicles/common/[VEHICLE]/[VEHICLE]_main_m.data.png",
        "metallicFactor": 1,
        "normalMap": "/vehicles/common/[VEHICLE]/[VEHICLE]_main_n.normal.png",
        "roughnessMap": "/vehicles/common/[VEHICLE]/[VEHICLE]_main_r.data.png"
      },
      {
        "ambientOcclusionMap": "/vehicles/common/[VEHICLE]/[VEHICLE]_main_ao.data.png",
        "baseColorMap": "/vehicles/[VEHICLE]/SKINNAME/[VEHICLE]_skin_SKINNAME.dds",
        "diffuseMapUseUV": 1,
        "clearCoatFactor": 1,
        "clearCoatMap": "/vehicles/common/[VEHICLE]/[VEHICLE]_main_cc.data.png",
        "metallicFactor": 0.5,
        "normalMap": "/vehicles/common/[VEHICLE]/[VEHICLE]_main_n.normal.png",
        "opacityMap": "/vehicles/[VEHICLE]/[VEHICLE]_skin_o.data.png"
      },
      {},
      {}
    ],
    "activeLayers": 2,
    "dynamicCubemap": true,
    "materialTag0": "beamng",
    "materialTag1": "vehicle",
    "version": 1.5
  }
}

The map paths in the first stage differ between vehicles. Copy them from the vehicle's own entry rather than typing them, and check that each file exists in the vehicle's zip (or in common). Some vehicles, such as the Percheron, split a skin over several materials (percheron_body.skin.NAME, percheron_body_paint.skin.NAME): copy each of them.

5. Tips

Template on top View › Template on top (or the checkbox on the template layer) lays the wireframe over your artwork, so you can see the panel edges while painting. It isn't exported.
Text on both sides A linked mirror is an exact mirror image, so mirrored text reads backwards on the template. Depending on how the car's sides are laid out, it can still read correctly in game, or not; check in game, and if it's backwards, use a plain copy (Ctrl+D) instead of a mirror.
Smaller files The .dds export is lossless and large (a 4096 × 4096 skin is 64 MB). Convert it to BC7 with texconv -f BC7_UNORM_SRGB -m 0 file.dds, Paint.NET or Photopea for a file about four times smaller.
Photos and logos Drop images (or .dds files) onto the canvas, or paste them. Rasterize a vector to recolour it as a picture with the Tint control.
Keyboard Press ? in the studio for every shortcut.
Photopea for masks and photo work

6. Troubleshooting

The skin isn't in the Paint Design list Check the jbeam's slot type (paint_design) and that the mod folder is mods/unpacked/[mod]/vehicles/[vehicle]/. Reload the vehicle with Ctrl+R, or restart the game after adding new files.
The skin is listed but the car looks plain The material name doesn't match the skin name, or the texture path is wrong. Compare all three names letter by letter.
The design lands on the wrong panels The template didn't match the vehicle or variant. Use the vehicle's own UV template from your install.
A DDS won't open The studio reads BC1–BC5, BC7 and uncompressed RGBA. HDR formats such as BC6H aren't supported; open those in Photopea and save as PNG.
A font looks wrong after reopening The studio loads its fonts from Google Fonts, so it needs to be online when it opens.
